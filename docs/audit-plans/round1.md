## 执行顺序（分批，每批出证据）

1. **批 0**：A1~A7 静态扫描（1 个脚本，输出问题清单）
2. **批 1**：B1~B6 宿主契约（1 个脚本，mock 全形态调用）
3. **批 2**：C1~C10 逻辑与状态机（1 个脚本，构造字节 + 时间注入）
4. **批 3**：D1~D5 功能矩阵（1 个脚本，源×档×形态矩阵）
5. **批 4**：E1~E4 性能（1 个脚本，采样 + 并发 + 长跑）
6. **批 5**：F1~F5 安全健壮性（1 个脚本，畸形输入）
7. **批 6**：G1~G3 运维闭环（脚本 + 人工比对表）
8. **批 7**：H1~H4 文档一致（跑仓库门禁 + 跨仓脚本）
9. **批 8**：I1~I5 边界与回滚（脚本）
10. **批 9**：汇总报告 → 缺陷分级（阻断/严重/一般/建议）→ 修复阻断与严重 → 复跑全部门禁

## 验收标准

- 每个 ID 有 `passed / failed / blocked` 三态之一，`failed` 必须给出触发路径、影响面、修复或明确不修的理由
- 汇总报告数字必须是本轮命令的真实输出，不得引用历史结论
- 修复任何缺陷后，A1 + 冒烟 67 + 压测 32 + 该 ID 的专项探针 必须同时复跑通过
- 全程不动三仓的 commit / push（用户决定）
