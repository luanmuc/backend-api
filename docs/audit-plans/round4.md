## §0 为什么需要这一轮：已暴露的自身错误清单

不是"再跑一遍绿字"，而是拿**已经发生过的错误**当靶子。前三轮实际犯过：

| # | 错误 | 后果 | 为什么会发生 |
|---|---|---|---|
| 1 | T2 归因错：把源级冷却判成"限速窗口打满" | 提出两个改方案，全是解决不存在的问题 | 冷却与限速**抛同一个错误码** `RATE_LIMIT`，只看了码没看 message |
| 2 | T2 原判据鉴别力不足（`a3<a1 && a3>0`） | 比值 0.9 也能过，等于没测 | 只要求"单调下降"，没要求"降到 1/3" |
| 3 | T3 判据读未导出变量 | `undefined` → `Object.keys` 恒 0 → 恒真空断言 | 没核对 `module.exports` 到底有没有它 |
| 4 | U3 把 bash 注释当 H1 | 误报 | 没跟踪 ``` 围栏 |
| 5 | U9 把宿主降级通道当调试残留 | 误报 | 没读 `console.log.bind(console)` 的上下文 |
| 6 | W5/W6/W7 读错导出名与字段名 | 三条断言全错 | 凭印象写，没先 `node -e` 打真实导出面 |
| 7 | U6 自指 + 文档描述被当违规 | 脚本永远报自己 6 次 | 全文匹配，没处理"被检查对象在描述规则" |
| 8 | 修 D-16 时给不存在的 `main` 加导出 | require 直接报错 | 没先确认脚本里有没有 `main` |
| 9 | 49→58 口径未随提交更新 | 矩阵漏 2 行、全部文档数字过期 | 提交改动了分母，但没人重算 |

**共性**：几乎全部是「凭印象判断、没先取真实值」+「判据写完就信，没做反向验证」。本轮的判据就是针对这两条设的。

解析 `coverage-*.json` 里 `lx-source.js` 的 `ranges`，算出未执行行区间，输出：

- 未执行行数与占比
- 未执行区间对应函数名（按最近上文 `function xxx` 定位）

### 7.2 M1 变红 → 定性为 mock 缺省（不是产品缺陷）

M1 改真判据后首跑红：`r1=LINK_EXPIRED r2=RATE_LIMIT；总外呼=12`。

隔离复现（`maxConcurrency=1`）：

| 场景 | 结果 |
|---|---|
| 单路，scene 对所有 URL 返 JSON | **LINK_EXPIRED**（外呼 12） |
| 单路，scene 对音频直链返音频 | **成功**（外呼 3） |
| 双路，同上修正后 | **一路 OK + 一路 RATE_LIMIT**（外呼 3） |
| 双路 `maxConcurrency=1e6` | 两路都 OK（外呼 6） |

结论：**单路也红 ⇒ 不是并发自锁**；根因是 mock 违反"非 binary 探针也走 `request`，scene 必须对音频直链返回音频"（`TESTING.md` §二.1）。已修正 M1 场景，断言转绿。
