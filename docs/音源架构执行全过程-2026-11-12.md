## 一、一句话结论

`lx-source.js` 仍是单文件聚合音源，但执行链路已经从“多源竞速拿链”升级为**三层收口**：

1. **L0 产物归一**：任何宿主返回形态（Buffer / Uint8Array / `{type:"Buffer",data}` / base64 信封）先归一成字节；
2. **判据层验真**：1KB Range + 真实时长/格式校验，片段、JSON、空体、错歌不再被当成功交付；
3. **L4 单一裁决**：`admit()` + `ADMISSION_POLICY` 决定“成功/失败码/TTL/证据等级/是否记账”，执行层只上报事实。

跨仓侧：App 通过 `builtin_source.js` 内置源，Release 构建时用跨仓版本闸门校验；v8.12.5 已进入 b115（历史）；v8.13.0 为源侧本地完全体，尚未推送，内置源与源仓 Release 资产字节一致。

## 三、当前架构与调用链

### 3.1 八段结构

| 段 | 职责 | 本轮关键变化 |
|---|---|---|
| ① 常量与配置 | `USER_CONFIG`、`SOURCE_TOGGLES`、错误码、预算 | 配置白名单扩到 28 数字 + 9 布尔；`crossPlatformEnabled` 可写 |
| ② 开关与探测 | 开关真值、探针素材、冷启动预热 | 关源/重开统一清账；冷启动探针超时独立配置 |
| ③ 日志/缓存/断路器 | LRU success 500 / fail 300、健康分 | 失败缓存按码/TTL 归一，不再把网络失败当“歌不存在” |
| ④ HTTP/判据/L0/L4 | 请求、Range 探针、验真、裁决 | L0 `toBytes/kindOf`；L4 `admit/applyAdmission` |
| ⑤ 匹配工具 | 歌名归一、hash/mid、平台映射 | 跨平台候选严格歌名 + 歌手 + 时长 ±5s |
| ⑥ 源实现 | 12 个登记源（10 上链 + 2 观察） | 星海后端缺 id 改 `PARAM_ERROR`，不再兜底 1 号歌 |
| ⑦ 注册表与调度 | 建链、竞速、降级、健康快照 | `structuralSkipReason` 无副作用过滤；`fallbackRace` 用 `attempts + admit` |
| ⑧ 上报与事件 | `on(request)`、`inited`、导出面 | `inited` 声明 `fallbackOwner` 与 `mediaEnvelope` |

### 3.2 一次取链的关键顺序

```
musicUrl
→ buildSourceChain（平台/音质/能力/跳过片段源/源数上限）
→ fallbackRace（分批错峰并发）
→ wrapExecute（冷却 → 断路器 → 并发/限速 → getUrl → validateUrl）
→ probeAudioDelivery / verifyDelivery（字节、格式、真实时长、片段判据）
→ admit（probe/delivery/attempts/error.code → verdict + 码 + TTL + 证据）
→ applyAdmission（唯一记账 reducer）
→ 成功写 successCache（按实际交付音质分槽）
```

**硬规则**：交付类错误码优先于业务码；弱证据 TTL 一律 ≤60s；`playDead` 只能由 strong 证据置位；片段兜底必须有 hash/mid 锚点。

## 四、关键决策与取舍

| 决策 | 原因 | 代价/边界 |
|---|---|---|
| 保留单文件，不拆模块 | QuickJS 宿主按单脚本导入，拆分只会增加构建/版本同步成本 | 文件已到 4509 行，靠 DEV_GUIDE 行段表维护 |
| 判据层先验真再交付 | 5 秒试听、JSON、空体都曾“能播但没声/错歌” | 每次交付多一次 1KB Range，计入预算 |
| L4 单一 `admit()` | 六处各自记账导致码被吞、TTL 不一致 | 新增分支必须过策略表，改动面集中 |
| 跨平台兜底只换“确定性失败” | 慢主平台仍有成功可能，过早换平台会误杀 | `NETWORK_TIMEOUT` 等 6s grace；结果缓存 10min |
| `fallbackOwner=source` | App 与源双层换源会重复搜索、重复耗时 | App 必须识别声明，旧源缺字段时回退主平台 |
| 桥媒体用 base64 信封 | 宿主 `JSON.stringify(Buffer)` 会把二进制变普通对象 | 大响应按 256KB 分片；`byteLength` 不符拒绝 |
| 历史 tag 不移动 | 追溯与 Release 资产必须可复现 | `v8.12.2` 的 CI 红保留为历史事实 |
