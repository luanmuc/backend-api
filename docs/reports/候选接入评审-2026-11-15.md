## 关键证据

### 1. `qingliang` tx 线路：真全曲

线路：`POST https://music.lzmhhh.com/api/music/url`（`type=qq`，带 Referer）

- 取链返回 `code:1 / 获取成功`，`data` 为 `aqqmusic.tc.qq.com` 直链。
- `Range: bytes=0-1023` → **HTTP/2 206**，`content-range: bytes 0-1023/10792943`，`content-type: audio/mpeg`。
- 全曲 **10,792,943 bytes**（≈11 分钟 @128k），不是片段。
- mock 加载上报 `inited`：4 源（tx/wy/kw/kg），actions `musicUrl`；静态提取平台 5 个、音质 128k/320k/flac。

其余线路（同仓内）：`api.yutangxiaowu.cn`（wy）、`ncm.kangqiovo.com`（wy）、`metings.qjqq.cn`（wy）、`ffapi.cn`（wy）、`api.bileizhen.top`（wy，直接返回重定向链）、`c.wwwweb.top`（kw/kg）。

#### 1.1 能不能用：5 首矩阵 + 可播性实测（R40 补测）

用 QQ 官方搜索接口取 mid（避开第三方搜索），再逐首走 qingliang tx 线路：

| 歌 | mid | 时长 | HTTP | 总字节 | 折算码率 |
|---|---|---:|---|---:|---|
| 晴天 | `0039MnYb0qxYhV` | 269s | 206 | 10,792,943 | ≈321k |
| 稻香 | `003aAYrm3GE0Ac` | 223s | 206 | 8,941,053 | ≈321k |
| 孤勇者 | `003UkWuI0E8U0l` | 256s | 206 | 10,242,283 | ≈320k |
| 起风了(旧版) | `0004jPDk2eB2dt` | 312s | 206 | 12,519,132 | ≈321k |
| 七里香 | `004Z8Ihr0JIu5s` | 299s | 206 | 11,970,297 | ≈320k |

**5/5 全是全曲 320k MP3**（`bytes × 8 / duration` 折算 320k，头部为 `ID3\x03` 合法标签），不是试听片段。

可播性（决定 App 能不能直接吃这条链）：

- **裸请求**（只带 `Range`、不带 UA、不带 Referer）→ **HTTP/2 206 + audio/mpeg**；
- 带移动端 UA → 同样 206；
- 把 `http:` 换 `https:` → 同样 206（播放器走 https 没问题）。

也就是说这条链**不依赖 Referer、也不依赖特定 UA**，`react-native-track-player` 拿到就能播。取链本身才需要 `Referer: https://music.lzmhhh.com/`。

**风险**：①第三方个人接口，无 SLA，单点；②链带 `vkey`，**有时效**（QQ 侧通常数小时级），必须"每次播放前取链"而不是缓存 URL；③原脚本带 hedge/取消/冷却，移植要保留其超时语义，不能直接抓 URL 就算接入；④`wwwweb`/`bileizhen` 与我们退役的 `c.wwwweb.top` 同域。

### 2. `xinglan` 主线路：试听片段（D-20 同型）

线路：`https://api.vkeys.cn/v2/music/tencent/geturl`（quality=4）

- 返回 `quality: "音乐试听"`，`url` 前缀 `ws.stream.qqmusic.qq.com/RS0...`（RS0 = 试听文件）。
- `Range: bytes=0-1023` → 206，`content-range: bytes 0-1023/960887`。
- **960,887 bytes vs qingliang 全曲 10,792,943 bytes**，相差 11.2 倍。
- 脚本声称的 v3 降级 `music/tencent/song/link` 本轮直接报 `code:110000 / HTTP客户端异常 500011`，等于**降级路径当前不可用**。

也就是说：星澜"母带/全景声"的卖点在无版权曲上会落到试听片段；若接入，必须走我们的 `PREVIEW_FRAGMENT` 判据（`VERIFY_DUR_RATIO` + `VERIFY_MIN_ORIGINAL_SEC`），并且要处理它**自带的** RS0 检测（否则两层检测会互相打架）。

另外：74KB / 1643 行、`_u()` 字符位移混淆、写死卡密（`6C1F-53W0-GRKI-EVFG`），维护成本与合规风险都高于收益。

### 3. `feichangdao` / `suyin`：同源复用

- `feichangdao` 的端点表：`api.chksz.top`、`music-api.gdstudio.xyz`（**我们已列入 `EXCLUDE_DOMAINS`**）、`oiapi.net` QQ/163/Kuwo、`api.xcvts.cn` 咪咕、`musicapi.haitangw.net` / `music.haitangw.cc` / `music.nxinxz.com`（changqing/念心模板）、汽水（`api-vehicle.volcengine.com` + `api.qishui.com`）。
- `suyin` 只有 `oiapi.net` + `api.xcvts.cn`，key `oiapi-ef6133b7-…` 与我们现有溯音系**同一个 key**。
- 两者都不能补 tx 覆盖（`suyin` 的 tx 走的还是 oiapi QQ，和我们 `suyinQQ` 一致，且 `suyinQQ` 本身是观察源）。

## 建议的接入顺序（若你要做）

1. **只接 `qingliang` 的 tx 线路**，作为 `juheTx` 的第二源（`juheTx` 已连续 7 天失败）：
   - 新登记一个 `qingliangTx`（`probation` 起步，`tx` 平台），复用现有 `PROVIDER_CONTRACT` 与验真链；
   - 保留其 3s 请求超时 + hedge 取消语义，不要退化成"串行等一个 URL"；
   - 接入时必须带 `PREVIEW_FRAGMENT` 判据（这条线路虽给全曲，但第三方随时可能改）。
2. **不整包接 `xinglan`**；只把它"官方后端检测 `freeTrialInfo` / RS0 前缀"的思路与我们现有 `PREVIEW_FRAGMENT` 判据做对照（我们现在是靠时长比 + 最小原曲时长，能覆盖）。
3. `feichangdao` / `suyin` 归档为「同源重复，不接入」，写进 `docs/SOURCE_RETIREMENT.md` 的判否留档，避免下次生态扫描又当新候选报出来。
