## 1. 定案缺陷

### P1-01 `playDead.quality` 导出→恢复不对称（v8.16.4 疑-31 修复只做了一半）

- 证据：导出含 `playDead.quality`（产物 `:5666` / `src/core/28-health-export.js`）；恢复侧 sanitized 只写 `{streak, deadline}`（产物 `:6171` / `src/core/18-health-persist.js:105`），随后却读 `item.playDead.quality`（产物 `:6211` / `18-health-persist.js:149`）→ 恒为 undefined → `playDeadQuality.delete(id)`。
- 复现：R1-01/02/03 绿、**R1-04 红**（bump flac → 导出含 flac → restore ok → 恢复后 `playDeadQuality=undefined`，streak=1 仍在）。
- 影响：App 重启 + `restoreHealthState` 后，跨档豁免静默退化为源级——正是 v8.16.4 声称修掉的「重启后高档失败又把整源摘掉」。
- 为什么漏网：App E22 往返夹具不含 `playDead.quality`；音源 RF21 只测 bump 归因，不测 export→restore 全字段等价。
- 修法（发布窗口）：sanitized 携带 `quality`（校验 ∈ `HEALTH_QUALITIES` 或 `"*"`），补全字段等价回归。

### P1-02 `parseFlacTags` 用大端读 FLAC 小端长度字段 → FLAC 身份标签恒空

- 证据：FLAC VORBIS_COMMENT 的 vendor_length / comment_count / comment_length 按规范是**小端**；实现用 `u32At`（大端，产物 `:1239` / `src/core/08-media.js:29`）读这三处（产物 `:1350/1354/1358` / `08-media.js:148/151/154`）。vendorLen 被字节序反转成天文数字 → `q` 越界 → 恒返回 `{title:"",artist:""}`。
- 复现：构造合法 FLAC（小端长度，TITLE=晴天 / ARTIST=周杰伦）→ **R2-01/02 红**（解析全空）；对照组按小端读同一 buffer 解出两条评论（R2-03 绿，证明 buffer 合法）。
- 影响：FLAC 交付永远走「无标签」分支——`checkDeliveryIdentity` 的强 MISMATCH 判据对 FLAC 从不生效；`identityStrict` 源（xinghai）只剩「无标签+片段→拒」，「无标签+完整时长的错歌」放行。MP3（ID3）不受影响。
- 修法（发布窗口）：给 vorbis comment 三个长度字段加小端读法；补真实格式夹具（FLAC/ID3v2.3/2.4）红绿双向。

### P2-01 `getHealthSnapshot` 自称只读，实际写 `qualitySkipProbeAt`

- 证据：快照注释「只读不写状态」（产物 `:5209`）；但 `:5279` 遍历平台×档位调 `buildSourceChain` → `22-chain.js:269` `computeEligibility({qualityShortCircuit:true})` → `:570` 调 `isQualityHopeless(id,q,platform)` **不传 opts** → `setProbe` 默认 true → 写短路表（产物 `:3912`）。
- 复现：前置短路表空（R3-01）；`setProbe:false` 对照不写（R3-02）；调一次快照后表里出现 `helloworldKw:flac`（**R3-03 红**）。
- 影响：打开健康面板即「布防」短路探路窗口；`exportHealthState` 会带上纯浏览产生的条目。行为偏保守（不致错交付），但违反只读契约、污染持久化状态。
- 修法：peek/快照路径把 `setProbe:false` 透传进 `computeEligibility`→`isQualityHopeless`；补快照纯度断言（调用前后 `qualitySkipProbeAt` 指纹不变）。

### P2-02 `songInfoMatch` 与 juhe 只读 `.duration`，App 从不发该字段

- 证据：App `MusicInfo` 只有 `interval`（格式化字符串，`src/types/music.d.ts:45`）；搜索组装丢弃原始秒（`kw/musicSearch.js:81-92`）。音源主验真路径 `originalDurationSec` 有 `duration→dt→interval→songDuration` 回退（产物 `:1691`），**生产时长判据有效**；但 `songInfoMatch` 的 `tDur = normalizeDurationSec(songInfo?.duration)`（产物 `:1060` / `09-match.js:231`）与 juhe `interval: Math.round((songInfo?.duration||0)/1e3)`（产物 `:4308` / `25-handlers.js:254`）无回退 → 生产恒 0。
- 影响：suyinKuwo/suyinMigu 严格搜索的时长闸门在生产从不生效（歌名/歌手仍把关，匹配偏弱）；juhe 上游恒收 `interval=0`（上游是否消费未知）。
- 修法：两处改用 `originalDurationSec` / `normalizeDurationSec(interval||duration)`；补「只带 interval 的 musicInfo」夹具。

### P2-03 ID3v2.2 标签不支持

- 证据：`parseId3Tags` 帧头按 4 字符 ID + 4 字节尺寸解析（产物 `:1329-1331`）；v2.2 是 3 字符 ID + 3 字节尺寸 → 首帧即 break → 视为无标签。
- 影响：老 MP3（v2.2 标签）身份强判据失效，与 P1-02 同族但面窄。修法：按 major version 分支解析。

### P2-04 字节保底启发式不吃 `verifyDurRatio` 配置

- 证据：比例分支用 `cfg("verifyDurRatio")`（产物 `:1763`）；无时长时的字节保底 `minFull = max(128e3, origDur*3e3*VERIFY_DUR_RATIO)` 用常量（产物 `:1769`）。
- 影响：面板调 `verifyDurRatio` 只影响一半判据。修法：统一走 cfg。

### P2-05 kuwoOfficial 搜索 `'`→`"` 清洗破坏含撇号歌名

- 证据：`raw.replace(/'/g,'"')`（产物 `:4045`）；歌名含 `'` 时 JSON 解析失败 → 回退 rid-only 正则 → name 空 → `titleMatch("",name)` 真但 `artistMatch(singer,"")` 假 → MISMATCH。
- 影响：边缘曲名误判 MISMATCH（而非 NOT_FOUND），失败缓存码偏严。修法：先试原始 JSON，再试清洗版。

### P2-06 探测通过复位源级熔断器，不复位档位熔断器

- 证据：`applyProbeResult` PASS 分支强制 `br.state="closed"`（产物 `:5113-5121`），不动 `byQuality[*].breaker`、不调 `syncSourceBreaker`。
- 影响：快照 `state=closed` 而各档仍 open，`eligible=false`——展示与资格口径分叉（行为保守，不致错交付）。修法：PASS 复位后走 `syncSourceBreaker` 或同复档位。

## 3. 架构/流程整体评估

**结论：框架与主流程设计成立，没有结构性问题。** 分层清晰（host→net→media→verify→verdict→dispatch→chain→health→persist），单一准入裁决 + 证据分级、档位账本与源级熔断器同步、探测与播放流量隔离、持久化白名单 + 禁字段扫描 + 版本/TTL/容量闸门、取消令牌全链传播、所有 Map 有界。本轮 2 个 P1 都是**局部实现错误**，不是架构错误。

**系统性弱点（为什么 589 条审计断言没拦住）：**

1. **半截修复能存活**：export 加了字段、restore 没接，往返测试只断言挑选字段而非全字段等价（E22 夹具缺 `playDead.quality`）。→ 补「导出→恢复全字段等价」断言。
2. **二进制解析缺真实格式夹具**：FLAC 字节序错误在纯字符串/URL 类断言面之外。→ 补 FLAC/ID3 真实字节夹具。
3. **「只读」声明无纯度测试**：快照写状态靠注释承诺。→ 补调用前后状态指纹断言。
4. **跨仓字段契约靠默契**：App 只发 `interval`，音源两处只读 `duration`，主路径有回退所以没炸。→ 把「musicInfo 字段契约」写成双侧断言。
5. **复核日期无门禁**：过期静默。→ 契约校验加新鲜度告警。
